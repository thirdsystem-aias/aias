## Security incident appendix

**What happened:** Mid-day, the assistant gave a buggy diagnostic shell command intending to redact API key values. The `${VAR:-default}` substitution actually expanded to the variable's *value* when set, not a placeholder. Three API keys (Anthropic, OpenAI, SerpAPI) printed in plaintext to terminal output and conversation history.

**Mitigations applied:**
- All 3 keys revoked at provider consoles
- Fresh keys generated and placed in `~/aias/.env`
- `~/aias/.env` permissions tightened to 600
- `.env` added to `~/aias/.gitignore` (commit 9141937)
- Verified `.env` was never historically committed
- SerpAPI key migrated from launchctl to `.env` for consistency

**Future-proofing:** Auto-load of `~/aias/.env` added to `~/.zshrc` for new terminals. Safe verification pattern adopted (length-only checks, no value display).

**No data loss.** All keys revoked before any third-party access could occur. Acquisition pipeline ran on the new keys without issue (288/288 OK after fill-in-the-gaps retry).
